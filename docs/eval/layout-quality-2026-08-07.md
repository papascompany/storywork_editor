# 배치 품질 지표 baseline — LAYOUT-04 (2026-08-07)

> 측정: `pnpm adoption:measure` (품질 섹션) · 상세는 `--verbose` · JSON 은 `pnpm adoption:report`
> 조건: 코퍼스 `data/eval/scripts/` 21편 / 217장면 · B5(preset-b5-novel) · seed 0 · LLM/DB 미사용
> 지표 정의 정본: `packages/ai-layout/src/quality.ts` 문서 주석

## 0. 왜 새 지표가 필요했나

채택률(`adoption.ts`)은 **"반드시 고쳐야 하는 결함이 0인가"** 만 본다. LAYOUT-03 → SCRIPT-KO-04 를
거치며 그 값이 100% 로 **포화**됐다 — 더는 배치가 좋아졌는지 나빠졌는지 구분하지 못한다.
결함이 없다는 것과 잘 그렸다는 것은 다른 말이다.

## 1. 독립 축과 의존 축

배치기(`bubble-cost.ts`)가 **최소화하도록 설계된 항**을 그대로 품질 지표로 쓰면 "우리가 최적화한
것을 우리가 잘한다고 보고"하는 순환이 된다. 그런 축은 품질의 증거가 아니라 **회귀 감시**용이다.

| 축 | 구분 | 무엇을 재나 |
|---|---|---|
| `balance` | 독립 | 면적 가중 무게중심이 지면 중앙에 있는가 (배경 제외 — 포함하면 전부 정중앙이 된다) |
| `density` | 독립 | 지면 점유율이 적정 범위(0.25~0.85)인가 — 과소는 허전, 과다는 "다닥다닥" |
| `dialogueDensity` | 독립 | 페이지가 감당하는 대사 수가 적정 범위(2~6)인가 |
| `readingFlow` | **의존** | 대사 순서대로 이은 말풍선이 읽기 순서(위→아래·좌→우)를 역행하지 않는가 |
| `faceClearance` | **의존** | 말풍선·캡션이 인물 얼굴을 덮지 않는가 |

`readingFlow` 는 `meta.lineIndex` 로 대사 순서를 복원한다 — 레이어 배열은 zIndex 로 정렬되므로
배열 순서로는 읽기 순서를 알 수 없다(이번에 레이어 계약에 `lineIndex` 를 추가한 이유).

## 3. 지표가 곧바로 찾아낸 것 — 프리셋 슬롯 결함

**의존 축인데 값이 낮으면 그건 회귀 신호다.** `faceClearance` 62.7% 가 그랬다. 배치기가 얼굴 가림을
비용에 넣고 최적화하는데도 낮다는 건, 배치기가 고를 수 있는 자리 자체가 잘못됐다는 뜻이다.

원인 분해(포즈 있는 157 페이지):

| 대상 | 최악 가림 평균 |
|---|--:|
| 말풍선 | **51.8%** |
| 캡션 | 0.5% |

템플릿·슬롯으로 좁히면 원인은 하나였다:

| 슬롯 | 가림 평균 | 배치 횟수 |
|---|--:|--:|
| `preset-1on1-talk` / `bubble-left` | **51.8%** | 157 |
| `preset-1on1-talk` / `bubble-right` | 0.0% | 132 |
| 생성 슬롯 `gen-bubble-N` | 0.0% | 202 |

`bubble-left` 는 이름과 달리 **우상단**(x 0.48 · y 0.05)에 있었고, 그 자리가 정확히 `pose-right` 의
얼굴(x 0.65~0.87 · y 0.1~0.38)이었다. 포즈가 y 0.1~0.9 를 차지하므로 상단에는 얼굴을 피할 폭이
아예 없다. **말풍선 두 개를 하단 좌우로 나란히** 옮겼다(x 0.04/0.52 · y 0.62 · w 0.44 · h 0.28) —
이름과 위치가 맞고, 좌→우 읽기 순서와도 맞는다.

생성 슬롯이 처음부터 0.0% 였던 것에 주목할 만하다. LAYOUT-03 이 도입한 "얼굴 가림 비용 오름차순
채택"은 제대로 작동하고 있었고, 손으로 적은 프리셋 좌표만 검증을 받지 않았던 것이다.

## 4. 남은 것 — 다음 개선 대상

- **구도 균형 50.7%** 가 가장 낮다. 말풍선을 하단으로 모으면서 무게중심이 아래로 내려간
  트레이드오프가 포함돼 있다(57.0% → 50.7%). 균형을 되찾으려면 말풍선을 위아래로 분산해야 하는데,
  1on1-talk 는 포즈가 상단을 다 차지해 자리가 없다 — **포즈 슬롯 기하부터** 손대야 한다.
- **지면 밀도 62.5%** — 겹침을 빼지 않은 근사값이라 과대 추정 쪽이다. 정확히 재려면 합집합 면적이
  필요하다.
- **얼굴 가림 잔여 3%** 는 프리셋이 아니라 생성 슬롯 격자의 **상단 중앙 칸**이 두 인물 얼굴의 안쪽
  가장자리를 7~15% 무는 것이다. 슬롯을 5개까지 채우면 피할 자리가 없는 구조적 한계 —
  격자를 3열 고정이 아니라 얼굴 위치에 맞춰 생성하면 줄일 수 있다.
- **실사용 로그(FOLLOWUP-60)** 가 붙으면 실측 채택률이 정본이 되고 이 축들은 선행지표로 강등된다.
  그때 상관을 추적할 수 있게 baseline 을 남겨 둔다.
