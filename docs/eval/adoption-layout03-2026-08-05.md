## 1. 무엇을 바꿨나

### ① 대사 수용량 기반 페이지 계획 — `packages/ai-layout/src/capacity.ts`
`splitScenes()` 의 5규칙(R1~R5)은 **연출**만 본다 — 카메라 앵글, 감정, 장소. 담을 수 있는지는
보지 않는다. 그래서 대사 7개짜리 장면에 말풍선 슬롯 2개짜리 페이지가 배정됐다.

`planCapacityPages()` 를 분할 뒤에 놓아 **담을 수 있는가**로 다시 계획한다:

| 상황 | 처리 |
|---|---|
| 페이지가 쓸 템플릿 | 수용량 인식 매칭으로 확정하고 `templateId` 로 고정 (compose 가 재매칭해 표류하지 않게) |
| 합병 페이지가 대사를 못 담음 | **합병 해제** — 같은 컷 구성을 대사만 바꿔 반복하느니 컷마다 한 페이지 |
| 합병 페이지가 컷을 다 못 보여줌 | **합병 해제** (포즈 슬롯 < 컷 수) |
| 단일 장면이 수용량 초과 | 같은 장면을 **여러 페이지로 분할**(`lineRanges`), 마지막 페이지에 1개만 남지 않게 균등 배분 |

### ② 수용량 인식 템플릿 매칭 — `template-match.ts`
점수 계산 **전에** 구조적 실현 가능성으로 후보를 거른다.

- `필수 포즈 슬롯 수 ≤ 채울 수 있는 인물 수` — **baseline `empty-slot` 61건의 직접 원인**.
  화자가 0인 장면(일기·에세이의 지문 단독 장면)에 2인 템플릿이 붙어 `pose-left` 가 영구히 비었다.
- `포즈 슬롯 수 ≥ 페이지가 보여줄 컷 수` — 모자라면 컷이 사라진다.
- 둘 다 만족하는 후보가 없으면 (1)만, 그래도 없으면 전체 풀로 완화 — 매칭은 항상 성공한다.

점수에는 말풍선 수용량 항을 더했다(충분 +12 / 부족분 ×-3, 하한 -12).

### ③ 말풍선 슬롯 동적 생성 — `bubble-slots.ts`
safe area 안쪽 고정 격자(3열 × N행)에서 후보를 만들고, 기존 슬롯과 15% 넘게 겹치면 버린 뒤
**얼굴 가림 비용**(BUBBLE-02 `occlusionCost`) 오름차순으로 채택한다. 생성 슬롯은 `optional: true`.

페이지당 상한 `MAX_BUBBLES_PER_PAGE = 6` — 넘는 대사는 슬롯을 더 만들지 않고 **페이지를 나눈다**.
수용량 계산(`pageBubbleCapacity`)과 실제 생성(`withGeneratedBubbleSlots`)이 같은 함수를 쓰므로
"계획한 수용량 ≠ 실제 슬롯 수" 로 대사가 새는 경로가 없다.

### ④ 멀티 장면 말풍선 배치 재작성 — `compose.ts`
종전 멀티 장면 경로는 **첫 장면 대사만** 슬롯 순서대로 꽂았다(나머지 컷 대사는 통째 유실).
이제 페이지 전체 대사를 BUBBLE-02 비용함수로 배치하고, 화자 앵커를 `장면::인물` 로 키잉해
같은 인물이 여러 컷에 나와도 대사가 **자기 컷 근처로** 모인다.

## 2. 배치 실물 검증 (지표 말고 좌표)

채택률이 포화됐으므로 fabricJson 좌표를 직접 검사했다 — screenplay 20페이지 · 말풍선 72개:

```
safe area 밖 말풍선:      0
말풍선끼리 20%+ 겹침 쌍:  0
빈 텍스트 말풍선:         0
페이지당 최대 말풍선:     5  (상한 6)
```

테스트로 고정한 항목: 생성 슬롯의 safe area 준수 · 기존/생성 슬롯 상호 비침범 · 결정론 ·
분할 구간이 장면 전체를 **겹침 없이 정확히** 덮는지(대사 유실 0의 구조적 근거).

## 3. 골든 시나리오 G5 의 기대값 변경

`compose.test.ts` / `compose-e2e.test.ts` 의 G5(장면 4개 × 대사 4개 = 16)는 종전에
**1페이지 four-cut** 을 기대했다. 그 페이지의 말풍선 슬롯은 4개였으므로 **대사 12개가
경고 없이 버려지는 상태를 테스트가 정답으로 고정**하고 있었다.

지금은 합병을 해제해 4페이지가 되고 16개 대사가 모두 실린다. R2(4컷 합병) 자체의 커버리지는
`page-split.test.ts` 30케이스와 새로 추가한 **G5b**(대사가 수용량 안이면 합병 유지 + 4컷 포즈 배치)가 지킨다.

## 4. 남은 것 — 이 지표가 못 보는 것

1. **프록시 포화** — 채택률은 이제 변별력이 없다. 실사용 편집 로그(PostHog · FOLLOWUP-60)가
   붙으면 실측 채택률로 교체하고 이 프록시는 선행지표로 남긴다. 그전까지는 배치 **품질** 지표
   (구도 균형·시선 흐름·컷당 대사 밀도)가 별도로 필요하다.
2. **지문이 대사로 계산된다** — `AnalyzedLine` 에는 대사/지문 구분이 없다. 코퍼스 실측:

   | 형식 | 라인 | 화자 없음 |
   |---|--:|--:|
   | screenplay | 335 | 91 (27.2%) |
   | novel | 223 | 126 (56.5%) |
   | light-novel | 163 | 80 (49.1%) |
   | diary | 75 | 68 (90.7%) |
   | essay | 26 | 25 (96.2%) |

   장면 헤딩(`S#1. 시장 골목 국수집 / 아침`)과 지문(`낡은 미닫이문. 영란이 육수 솥을 젓는다.`)이
   말풍선 슬롯을 차지한다. 배치가 아니라 **파싱**의 문제이며(ai-script), 페이지 수 증가(217→255)의
   상당 부분이 여기서 온다. → **SCRIPT-KO-04** 로 등록(최초 SCRIPT-KO-03 으로 적었으나 기존 CSN
   스코어러 항목과 ID 충돌이라 정정).
3. **페이지 수 증가는 의도된 것** — 대사를 버리지 않으려면 지면이 더 필요하다.
   screenplay 10장면이 17~20페이지가 된다. 2번이 해결되면 자연히 줄어든다.
