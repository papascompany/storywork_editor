## 1. 무엇이 문제였나

`AnalyzedLine` 에는 대사/지문 구분이 없었다. 그래서 **모든 라인이 말풍선 슬롯 하나씩**을 차지했다:

- 씬 헤딩 `S#1. 대학병원 응급실 입구 / 밤` 이 말풍선에 들어갔다. 종전 정규식은 `씬`·`장면`
  접두만 알아 실무에서 가장 흔한 `S#N.` 형식을 놓쳤다(코퍼스 screenplay 5편 중 4편 = 헤딩 40줄).
- 지문 "사이렌이 젖은 아스팔트를 긁는다." 가 대사와 같은 자리를 두고 경쟁했다.
- 산문(novel/essay/diary)은 인용 없는 단락이 통째로 말풍선 한 칸을 먹었다.

화자 없는 라인 비율은 essay 96.2% · diary 90.7% · novel 56.5% · screenplay 27.2%(LAYOUT-03 실측).
페이지 수용량(말풍선 6개)이 금세 차고, 찰 때마다 페이지가 쪼개졌다 — screenplay 장면 10편이
페이지 17~20개가 된 원인이다.

## 2. 무엇을 바꿨나

### ① 라인 종류 — `packages/ai-script/src/types.ts` · `line-kind.ts`
`AnalyzedLine.kind: 'dialogue' | 'narration' | 'direction'` 를 도입했다. 파서가 항상 채우지만
필드 도입 이전에 저장된 SceneDoc 에는 없으므로, 소비 측은 `lineKindOf()` 를 거쳐 읽는다
(폴백 = 화자 있으면 대사, 없으면 서술 — 종전 동작과 동일).

### ② 씬 헤딩은 라인이 아니라 장면 속성 — `parsers/parse-screenplay.ts`
헤딩 정규식을 `S#1.` · `S 1:` · `#3.` · `씬 2:` · `장면 4.` · `INT./EXT.` 로 넓히고,
**구분자(`.`/`:`)를 필수**로 만들어 "장면이 바뀌었다" 같은 서술문의 오탐을 막았다.
헤딩 본문은 `SceneMeta.location` / `timeOfDay` 로 흡수한다 — 배치 대상이 아니라 장면의 속성이고,
배경 톤 추천(`getBgToneCandidate`)이 실제로 그 두 값을 쓴다.

지문(`[...]` · `(...)`)은 종전에 **통째로 버려졌다**. 이제 `direction` 으로 보존해 캡션으로 배치한다.

### ③ 캡션 박스 — `packages/ai-layout/src/caption-slots.ts` (신규)
서술·지문은 꼬리 달린 말풍선이 아니라 캡션 박스로 간다. 캡션 박스 하나가 **연속된 여러 줄을 묶는다**
(박스당 3줄 · 180자). 이것이 페이지 수용량이 늘어나는 실제 근거다.

기하는 말풍선과 **같은 격자**(`generateGridSlots`)를 쓴다 — 자리 계산·얼굴 가림 비용·겹침 회피가
이미 검증된 경로다. 말풍선을 먼저 만들고 캡션을 나중에 만들어 서로 침범하지 않는다.

### ④ 페이지 예산이 둘로 나뉜다 — `capacity.ts`
`PageBudget = { bubbles, captionBoxes }`. 대사는 말풍선 개수로, 서술은 캡션 박스 개수로 센다.
페이지 분할은 두 예산을 동시에 지키는 그리디 2패스다(1패스로 페이지 수 N 을 얻고, N 으로 페이지당
목표치를 낮춰 다시 잘라 마지막 페이지가 한 줄만 남는 배치를 피한다. 재분배가 페이지 수를 늘리면
1패스 결과를 쓴다).

수용량 계산과 실제 묶음이 **같은 함수**(`groupCaptionLines`)를 쓴다 — LAYOUT-03 이 말풍선에서
세운 원칙과 같다. 어긋나면 글이 조용히 사라진다.

## 3. 함정 하나 — PDF 줄간격

캡션을 개행(`\n`) 한 덩어리로 내보내면 pdf-lib `drawText` 가 **페이지 기본 lineHeight(24pt)** 로
줄을 내려 12pt 캡션이 박스를 넘친다(핸드오프 §5 기존 함정). 그래서 캡션 박스는 fabricJson 에서
**줄당 하나씩의 `text` 레이어**로 나가고, 줄 위치를 `ai-layout` 이 직접 계산한다.
회귀 가드: `adoption-regression.test.ts` — "캡션 레이어 텍스트에 개행이 없다".

레이어 종류는 Schema v1 의 기존 `'text'` 를 쓴다(신규 LayerKind 없음) — 편집기
(`layerKindToKind: text→text`)와 PDF 어댑터(`case 'text'`) 모두 이미 처리하는 경로다.
캡션임은 `meta.kind='caption'` · `captionBoxSlotId` · `captionLineIndex` 로 표시한다.

정답으로 박아둔 것이고, 대본 정보를 조용히 버리는 건 대사 유실과 같은 종류의 결함이다
(LAYOUT-03 의 골든 G5 기대값 정정과 같은 성격).

## 5. 남은 것

- **프록시 포화는 그대로다.** 채택률 100% 는 여전히 "구조적 결함 0" 까지만 말한다. 배치 품질
  (구도 균형·시선 흐름·컷당 대사 밀도)은 **LAYOUT-04** 의 몫이다. 이번 변경으로 페이지 수가
  장면 수에 수렴해 품질 지표를 재는 기준선이 오히려 깨끗해졌다.
- 캡션 박스 상한(3줄·180자)은 렌더 실측이 아니라 **보수적 추정**이다. 실제 폰트 메트릭 기반
  줄바꿈 계산은 편집기 텍스트 엔진과 공유해야 정확하다 — 넘침이 관측되면 그때 좁힌다.
- 산문 서술은 여전히 단락당 200자에서 잘린다(`parse-novel` 기존 동작). 캡션이 여러 줄을 담게 된
  지금은 문장 단위 분할이 더 나을 수 있다 — 별도 작업.
