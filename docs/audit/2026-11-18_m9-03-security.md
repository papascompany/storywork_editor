## 1. SSRF — PDF 이미지 fetch (수정)

**경로**: 로그인 사용자 → `POST /api/projects/save`(페이지 `fabricJson`) → `POST /api/projects/[id]/publish`
(또는 workers `pdf-build`) → `@storywork/pdf-engine` 이 레이어 `meta.fileUrl` · `fabric.src` · 표지
`coverImageUrl` 을 **서버에서 그대로 `fetch`**.

- 저장 스키마(`PageJsonV1Schema`)는 레이어 `fabric` 을 `z.record(z.string(), z.unknown())` 로만 검사 → URL 무제한
- 영향: 내부망·메타데이터 엔드포인트로 요청 가능(blind SSRF — PNG/JPEG 가 아니면 임베드 실패라 응답 본문 유출은
  제한적). **타임아웃·크기 제한이 없어** 거대한/끝나지 않는 응답으로 함수 메모리·시간 고갈 가능. 실패 URL 은
  프리페치와 페이지 렌더에서 두 번 요청됐다

**수정** (`packages/pdf-engine/src/render/image-fetch.ts`, 세 fetch 지점을 `getOrEmbedImage` 로 일원화):
- 허용: `data:image/png|jpeg;base64` (편집기 드롭 이미지) + https origin 허용 목록
  (`NEXT_PUBLIC_SUPABASE_URL` · `SUPABASE_URL` · 선택 `PDF_IMAGE_ALLOWED_ORIGINS`). 그 외는 **요청하지 않음**
- `redirect: 'error'`(허용 목록 우회 차단) · userinfo URL 거부 · 10초 타임아웃 · 25MB 상한(헤더 + 스트림)
- 실패 URL 캐시 → 같은 URL 재요청·중복 경고 없음
- 정상 출처 근거: 포즈 적재(`scripts/ingest-poses.ts`)·admin 업로드 모두 Supabase Storage 공개 URL,
  사용자 이미지는 `useImageDrop` 의 FileReader dataURL. web `next.config.ts` remotePatterns 도 Supabase 1곳
- 테스트 23개(`__tests__/image-fetch.test.ts`): 판정 표 14케이스 · 거부 URL 은 fetch 미호출 · 크기 상한 ·
  리다이렉트/시간 제한 옵션 · buildPdf 통합(169.254.169.254 미요청 + 경고 1회, data 이미지 임베드)

**운영 주의**: 이미지를 Supabase 밖(CDN 등)으로 옮기면 `PDF_IMAGE_ALLOWED_ORIGINS` 에 origin 을 추가해야
PDF 에 이미지가 들어간다. 빠지면 publish 결과 warnings 에 "허용되지 않은 이미지 출처" 가 남는다.

## 2. SVG XSS — 위반 없음

- 편집기는 외부 SVG 를 파싱하지 않는다(`loadSVGFromString/URL` 사용처 없음). 사용자 업로드는 PNG 만
- `editor-effects/pattern.ts` 의 SVG 는 코드가 만든 패턴을 `data:image/svg+xml` **이미지**로만 사용 —
  이미지 컨텍스트의 SVG 는 스크립트가 실행되지 않는다
- pdf-engine 허용 목록에서 `data:image/svg+xml` 은 거부(임베드 대상 아님)

## 3. 업로드 — 위반 없음

`apps/admin/app/api/resources/upload/route.ts`: curator 이상 권한 · 10MB 상한 · PNG 매직바이트 검증 ·
sharp 재인코딩(EXIF 제거) 후 파생본 생성. web 에는 서버 업로드 엔드포인트가 없다(사용자 이미지는 dataURL 로
페이지 JSON 에 포함 → 저장 API 의 본문 크기 제한 적용).

## 4. `dangerouslySetInnerHTML` — 위반 없음

테마 초기화 스크립트(상수)와 JSON-LD 4곳(`app/page.tsx` 모듈 상수, `app/faq/page.tsx` 의 `lib/faq-data`
정적 데이터)뿐. DB·사용자 입력이 들어가지 않는다. JSON-LD 에 동적 데이터를 넣게 되면 `</script>` 이스케이프 필요.
